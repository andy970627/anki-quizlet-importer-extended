# Odyssey — 故事與敘事設計

用荷馬史詩《奧德賽》的架構，把「返鄉之旅」改寫成一場恐怖遊戲。核心情緒不是血腥，而是**迷失感**——奧德修斯花了十年才回家，途中不斷被引誘、恐嚇、考驗要不要繼續前進。這個情緒剛好對應恐怖遊戲最基本的張力：玩家在黑暗中不知道該往哪走、該相信什麼。

## 一句話核心

> 你想回家，但海神不准你走——每次你以為快要逃出去了，祂就找到一個理由把你吹回島上。像薛西弗斯推石頭一樣，努力本身不會累積，只有「再試一次」。

## 神話依據：為什麼是「永遠逃不出去」

這個核心迴圈不是憑空套用薛西弗斯，而是奧德賽原典裡真的有的兩個設定：

- **波賽頓的詛咒**：奧德修斯弄瞎了獨眼巨人波呂斐摩斯（Polyphemus）——波賽頓之子——因此波賽頓發誓讓他的返鄉之路充滿阻撓，十年漂泊才到家。**海神的憤怒是整個故事「出不去」的真正原因**，不是意外、是懲罰。
- **卡呂普索島（Ogygia）的七年**：奧德修斯在返鄉途中被女神卡呂普索留在她的島上整整**七年**，哪裡都去不了，直到眾神介入才被放行。

把這兩個設定疊在一起：**玩家就是被海神盯上、困在島上第七年的奧德修斯。** 每次你造船出海、以為這次真的能逃出去，海神就會用「異常」考驗你——你沒注意到的不對勁，就是祂找到的藉口，一個巨浪就把你連人帶船打回島上。跟薛西弗斯的詛咒一樣：**過程中的努力不會留下痕跡，只有你這個人記得自己失敗過幾次。**

## 核心迴圈：出海 → 異常 → 被打回島上

這是整個遊戲的骨架，取代原本線性章節的設計：

1. **島上準備**：玩家在島上醒來（如果不是第一次，場景會帶著前一輪失敗的痕跡——例如海岸多了一塊浮木殘骸），修補/準備船隻，手電筒電量、物資在島上可以補給。
2. **出海**：划船離開海岸線，進入霧裡的海面。這段路途會放置幾個**異常檢查點**——星象不對、海浪方向跟風向矛盾、遠方燈塔的光是錯的顏色、甲板上多了一件不屬於你的東西。
3. **判斷異常**：玩家要在異常點做出反應（例如按鍵「標記異常」或選擇繞開/修正），判斷正確 = 繼續航行、離家更近一步；判斷錯誤或沒注意到 = 觸發海神的注意。
4. **被打回島上**：一旦被海神盯上，追逐／風暴機制啟動（可以直接延伸 `EnemyChaser.cs` 做成一隻具象化的海怪或巨浪本體追你），追上玩家＝這輪航行失敗，畫面一黑，玩家**重新在島上醒來**，回到步驟 1。這就是薛西弗斯的「石頭滾回山腳」。
5. **持續到成功或崩潰**：不是靠純粹重複過關，而是**玩家自己記住的經驗**在進步——這一點刻意呼應你另一個「數位設計原理」期末作品（北科光華館找異常迴圈）的核心機制：手冊記錄每次見過的異常，愈多輪之後愈能一眼認出「這個不對勁」。連續正確判斷夠多次／見完一輪完整的異常清單，才真正能逃出去。

### 異常的主題分類（沿用原本的章節典故，只是從「線性關卡」改成「每輪航行隨機抽取的異常池」）

| 異常類型 | 原典 | 在航行中長怎樣 |
|---|---|---|
| **忘憂果式誘惑** | 吃了忘憂果的人不想離開 | 海上突然風平浪靜、有音樂聲，畫面提示「在這裡休息」，但多待一刻鐘其實是陷阱——時間被偷走，等於沒有前進 |
| **獨眼巨人的怒吼** | 波呂斐摩斯被弄瞎後的詛咒源頭 | 遠方傳來巨大的怒吼聲，聲音愈來愈近代表祂（海神派來的巨浪／海怪化身）鎖定了你的船——對應 `EnemyChaser.cs` 用聲音/光線偵測 |
| **賽蓮的歌聲** | 歌聲引誘水手觸礁 | 耳邊傳來呼喚你名字的聲音，引導你把船划向看似捷徑、其實是暗礁的方向 |
| **喀耳刻的鏡影** | 把水手變成豬 | 海面倒影裡的自己表情不對、多了一隻手——玩家要判斷「這是不是異常」而不是直接被嚇跑 |
| **冥界的低語** | 奧德修斯到陰間問路 | 船底傳來亡者（過去失敗的自己）的聲音，有時候是提示、有時候是誤導，玩家要自己分辨能不能信 |

每輪航行從這個池子裡抽幾個異常出來組合，玩家永遠不知道這次會遇到哪幾種——這也呼應「不確定感」才是恐怖感的核心，而不是單純堆疊 Jump Scare。

## 敵人設計筆記：Polyphemus 為什麼要用「聲音」偵測

現有的 `EnemyChaser.cs` 用距離判斷偵測範圍，是很好的入門起點，但如果要呼應「獨眼巨人」的神話設定（牠很強、很兇，但感官不完整），可以把偵測條件換成：

- 玩家 `Flashlight` 開啟時，偵測範圍大幅提升（光 = 暴露自己）
- 玩家按下奔跑鍵時，短時間內偵測範圍也提升（腳步聲）
- 玩家蹲下、關手電筒、靜止不動時，即使距離很近也不容易被發現

這樣手電筒electricity（`Flashlight.cs` 的電量機制）就不只是資源管理，而是「開燈 vs. 被發現」的核心兩難決策，跟主題緊密扣在一起。

## 什麼會跨輪保留、什麼不會

迴圈結構最怕玩家覺得「每次都在做一樣的事很煩」，所以要分清楚**真的歸零**跟**悄悄進步**的東西：

- **歸零**：船的位置、這一輪走過的路線、還沒標記的異常——每次回到島上都重新出海。
- **保留**：玩家自己記得「上次那個燈塔顏色不對」（跟 `Class_Digital_design_test` 的手冊機制一樣，可以直接做一本可翻閱的「航海日誌」UI，自動記下玩家曾經標記過的異常描述）、島上場景會留下前幾輪失敗的痕跡（海岸愈堆愈多的浮木、船的傷痕），讓「第幾年」被困在這裡這件事有視覺上的重量。
- **結局條件**：連續一次完整航行中，正確判斷池子裡抽到的所有異常、且沒被海神的追逐抓到——玩家才真正駛出霧區，看到伊薩卡（家）的輪廓。可以設計成多重結局：真的到家、或者到了家才發現家也已經不對勁（跟原本「歸鄉未必圓滿」的主題呼應）。

## 情緒基調備忘

- **不用嚇血腥，用「不確定」嚇人**：賽蓮的呼喚聲該不該信？這次的異常是不是上次見過的那種？玩家的每個選擇都伴隨不確定的後果。
- **薛西弗斯式的疲憊感要被設計出來，而不是因為重複而偷懶**：每次被打回島上，畫面/音樂/島上場景可以有細微變化，暗示玩家的心理狀態隨著「第 N 年」逐漸崩潰——不是單純重播同一個開場。
- **道具/收集品**：奧德修斯的物件殘片（船槳碎片、羊皮繩、風袋）可以做成「航海日誌」解鎖要素，串起異常線索，玩起來像 `unity-game-dev-101/` 裡教的 `CoinPickup.cs` 概念，只是換成敘事碎片而非分數。

## 下一步

這個核心迴圈需要一支新的管理腳本來串起「出海 → 異常判斷 → 失敗送回島上 / 成功繼續」的狀態機，取代原本單純的 Game Over 邏輯。我建議的落地順序：

1. 先做 `VoyageLoopManager.cs`：管理「島上／航行中」兩個狀態、記錄本輪已標記的異常、失敗時把玩家傳送回島上重置場景。
2. 做 1-2 個 `AnomalyCheckpoint.cs`（異常檢查點）：玩家靠近時可以按鍵「標記異常」，正確/錯誤都回報給 `VoyageLoopManager`。
3. 把 `EnemyChaser.cs` 接上：被海神盯上後怪物開始追，追到＝呼叫 `VoyageLoopManager` 的失敗流程。
